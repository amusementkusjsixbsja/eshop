# 管理后台服务 (service-admin)

分类管理、商品管理、订单查看 — 由 小D 负责。

## 端口

- 外部：`8003`
- Nginx 前缀：`/api/shop/b-endpoint/*`

## 功能模块

### 1. 分类管理（`/b-endpoint/categories`）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/` | 全部分类列表 |
| POST | `/` | 创建分类（支持二级：parent_id 可选）+ 清除 Redis 缓存 |
| PUT | `/{id}` | 编辑分类（名称/父级）+ 防止自引用 |
| DELETE | `/{id}` | 删除分类（检查商品引用/子分类，有引用则拒绝）+ 清除缓存 |

### 2. 商品管理（`/b-endpoint/products`）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/` | 商品列表（支持 status 筛癣分页） |
| POST | `/` | 创建商品（分类验证 + 清除热门商品缓存） |
| PUT | `/{id}` | 编辑商品（部分更新 + 清除商品缓存） |
| PATCH | `/{id}/status` | 上下架（on_sale / off_sale + 清除缓存） |

### 3. 订单查看（`/b-endpoint/orders`）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/` | 所有用户订单（JOIN 用户昵称，支持状态筛癣分页） |
| GET | `/{id}` | 订单详情（含商品明细 + 用户信息） |

## 权限

所有管理接口需要 `role=admin`：
- `get_current_admin()` 中间件校验
- 普通用户访问返回 403

## 缓存策略

所有写操作（增/删/改）都会清除相关 Redis 缓存：
- `categories:tree` — 分类树
- `hot:products:list` — 热门商品
- `product:{id}` — 商品详情

## 技术要点

- 删除分类前检查 `shop.products` 和子分类引用
- 部分更新（PATCH）只更新非空字段
- 缓存清除确保用户端即时看到变更
